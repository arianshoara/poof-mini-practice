# POOF Mini Practice

A small learning project for exploring the core architecture of POOF.

یک پروژه‌ی تمرینی کوچک برای یادگیری معماری و سازوکارهای اصلی POOF.

## هدف پروژه

POOF Mini Practice نسخه‌ی اصلی و Production پروژه‌ی POOF نیست.

هدف این پروژه این است که پیش از ساخت پلتفرم اصلی، مفاهیم مهم آن را در مقیاس کوچک و قابل‌کنترل تمرین کنم:

- ساخت سایت چندصفحه‌ای
- کار با HTML، CSS و Vanilla JavaScript
- مدیریت Navigation مشترک
- طراحی رابط براساس داده
- خواندن اطلاعات از فایل‌های JSON
- ساخت دیکشنری کوچک
- ساخت و ذخیره‌ی کارت‌های شخصی
- استفاده از localStorage
- مدیریت تم‌ها
- نگه‌داشتن Context میان درس، داستان، دیکشنری و کارت
- یادگیری Git و GitHub

## مسیر اصلی یادگیری

درس یا داستان → انتخاب واژه → دیکشنری → ساخت کارت → مجموعه‌ی کارت‌ها

واژه هنگام انتقال میان این بخش‌ها باید جمله، منبع و Context اصلی خود را حفظ کند.

## فناوری‌های فعلی

این پروژه در حال حاضر از ابزارهای زیر استفاده می‌کند:

- HTML

- Vanilla JavaScript
- localStorage
- GitHub Pages

در مرحله‌ی بعد، فایل‌های JSON نیز به پروژه اضافه خواهند شد.

## خارج از محدوده‌ی فعلی

فعلاً این موارد ساخته نمی‌شوند:

- Backend
- دیتابیس واقعی

- Authentication
- هوش مصنوعی
- API دیکشنری خارجی
- React یا Frameworkهای دیگر

این فناوری‌ها ممکن است در نسخه‌های تمرینی بعدی اضافه شوند.

## وضعیت فعلی پروژه

### v0.3.0 — Data-driven Learn ✅

در این نسخه، صفحه‌ی Learn از یک صفحه‌ی ثابت به یک رابط داده‌محور تبدیل شده است.

اطلاعات درس‌ها داخل فایل `data/lessons.json` نگهداری می‌شود و فایل `js/learn.js` مسئول دریافت، بررسی، مرتب‌سازی و نمایش آن‌ها است.

### امکانات این نسخه

- ساخت `data/lessons.json`
- دریافت اطلاعات درس‌ها با `fetch`
- استفاده از `async/await`
- ساخت کارت‌های درس با DOM
- مرتب‌سازی درس‌ها بر اساس `order`
- نمایش عنوان، توضیح، سطح و زمان درس
- نمایش وضعیت Available و Coming soon
- پشتیبانی از Loading State
- پشتیبانی از Empty State
- پشتیبانی از Error State
- پشتیبانی از Success State
- اعتبارسنجی ساختار هر درس
- بررسی یکتابودن `id` درس‌ها
- بررسی یکتابودن `order` درس‌ها
- استفاده از `DocumentFragment` برای ساخت کارت‌ها
- سازگاری کارت‌ها با Classic و Snowy
- آزمایش Navigation با محتوای بلند Learn

### جریان فعلی داده در Learn

`lessons.json → fetch → validation → sorting → DOM rendering → lesson cards`

درس‌ها دیگر به‌صورت تکراری داخل `learn.html` نوشته نمی‌شوند.

فایل `learn.html` فقط ساختار صفحه و محل نمایش درس‌ها را فراهم می‌کند.

### قرارداد فعلی درس

هر درس باید شامل این اطلاعات باشد:

- `id`
- `order`
- `title`
- `description`
- `level`
- `estimated_minutes`
- `status`

مقدار `status` فقط می‌تواند یکی از این دو حالت باشد:

- `available`
- `coming_soon`

شناسه و ترتیب هر درس باید یکتا باشند.

### محدودیت‌های فعلی

نسخه‌ی فعلی هنوز شامل این قابلیت‌ها نیست:

- بازکردن صفحه‌ی کامل هر درس
- تمرین‌های داخل درس
- پیشرفت شخصی کاربر
- درس‌های تکمیل‌شده یا قفل‌شده
- دیکشنری
- ساخت کارت
- Deck
- مرور کارت‌ها
- حساب کاربری
- دیتابیس واقعی
- Backend
- هوش مصنوعی

این قابلیت‌ها در نسخه‌های بعدی و به‌صورت مرحله‌ای تمرین خواهند شد.

## وضعیت فعلی پروژه

### v0.4.0 — Storage Layer ✅

در این نسخه، یک لایه‌ی مشترک برای ذخیره و مدیریت کارت‌های شخصی ساخته شد.

فایل `js/storage.js` تنها بخش پروژه است که مستقیماً با `localStorage` کار می‌کند.

صفحه‌های دیگر برای مدیریت کارت‌ها از رابط عمومی `poofStorage` استفاده می‌کنند و نیازی ندارند نام کلید Storage یا نحوه‌ی تبدیل JSON را بدانند.

### امکانات این نسخه

- ساخت `js/storage.js`
- تعریف کلید مشترک Card Storage
- اضافه‌شدن `schema_version`
- ساخت ساختار خالی و معتبر Storage
- خواندن امن اطلاعات از `localStorage`
- نوشتن امن اطلاعات در `localStorage`
- مدیریت خطاهای `JSON.parse()`
- تبدیل Object به JSON با `JSON.stringify()`
- اعتبارسنجی ساختار اصلی Storage
- اعتبارسنجی ورودی کارت
- اعتبارسنجی کارت‌های ذخیره‌شده
- تولید شناسه‌ی یکتا برای کارت
- ثبت `created_at`
- ثبت و به‌روزرسانی `updated_at`
- بررسی یکتابودن شناسه‌های کارت
- جلوگیری از تغییر `id` هنگام ویرایش
- جلوگیری از تغییر `created_at` هنگام ویرایش
- نمایش تعداد کارت‌ها در صفحه Cards
- جداسازی اطلاعات عمومی دیکشنری از کارت شخصی

### رابط عمومی Storage

عملیات فعلی:

- `getCards()`
- `getCardById(cardId)`
- `addCard(cardInput)`
- `updateCard(cardId, changes)`
- `deleteCard(cardId)`

صفحه‌ها نباید مستقیماً از این دستورات استفاده کنند:

- `localStorage.getItem()`
- `localStorage.setItem()`
- `localStorage.removeItem()`

### ساختار فعلی Storage

اطلاعات کارت‌ها زیر کلید `poof-mini-card-storage` ذخیره می‌شوند.

ساختار اصلی شامل این موارد است:

- `schema_version`
- `cards`

نسخه‌ی فعلی Schema برابر `1` است.

### جریان فعلی ذخیره‌سازی

`Cards or future Card Builder → poofStorage → storage.js → JSON → localStorage`

هنگام خواندن، جریان معکوس اجرا می‌شود:

`localStorage → JSON.parse → validation → poofStorage → Cards page`

### نتیجه‌ی آزمایش

در جریان آزمایش دستی:

- یک کارت نمونه ذخیره شد
- تعداد کارت‌ها از صفر به یک تغییر کرد
- کارت بعد از Refresh باقی ماند
- تغییر Theme روی کارت اثر نگذاشت
- کارت نمونه حذف شد
- کارت حذف‌شده بعد از Refresh بازنگشت
- Storage مرورگرهای مختلف مستقل باقی ماند

کنترل‌های آزمایشی پس از تأیید عملکرد حذف شدند.

### محدودیت‌های فعلی

Storage فعلی:

- فقط متعلق به یک مرورگر و دستگاه است
- میان دستگاه‌ها همگام نمی‌شود
- حساب کاربری ندارد
- Backup خودکار ندارد
- Migration واقعی ندارد
- Database تولیدی نیست
- نباید برای رمز، Token یا API Key استفاده شود

عملیات `getCardById()` و `updateCard()` در Card Builder واقعی آزمایش خواهند شد.

در نسخه‌ی بعد، یک فرم واقعی برای ساخت کارت شخصی ایجاد می‌شود.

Card Builder در ابتدا شامل این فیلدها خواهد بود:

- یادگیری فرم‌های HTML
- آشنایی با `label` و `input`
- مدیریت رویداد `submit`
- جلوگیری از Refresh ناخواسته‌ی فرم
- خواندن مقدار فیلدها
- نمایش خطاهای Validation
- نمایش پیام موفقیت
- پاک‌کردن فرم بعد از ذخیره‌ی موفق
- نمایش کارت ذخیره‌شده در Cards
- آزمایش واقعی `getCardById()`

کارت‌ها ابتدا به‌صورت دستی ایجاد می‌شوند تا رفتار Card Builder و Storage به‌صورت مستقل فهمیده شود.
