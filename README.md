# POOF Mini Practice

A small learning project for exploring the core architecture of POOF.

یک پروژه‌ی تمرینی کوچک برای یادگیری معماری و سازوکارهای اصلی POOF.

## هدف پروژه

POOF Mini Practice نسخه‌ی اصلی و Production پروژه‌ی POOF نیست.

هدف این پروژه این است که پیش از ساخت پلتفرم اصلی، مفاهیم مهم آن را در مقیاس کوچک و قابل‌کنترل تمرین کنم:

- ساخت سایت چندصفحه‌ای
- کار با HTML، CSS و Vanilla JavaScript
- مدیریت Navigation مشترک
- طراحی رابط براساس داده
- خواندن اطلاعات از فایل‌های JSON
- ساخت دیکشنری کوچک
- ساخت و ذخیره‌ی کارت‌های شخصی
- استفاده از localStorage
- مدیریت تم‌ها
- نگه‌داشتن Context میان درس، داستان، دیکشنری و کارت
- یادگیری Git و GitHub

## مسیر اصلی یادگیری

درس یا داستان → انتخاب واژه → دیکشنری → ساخت کارت → مجموعه‌ی کارت‌ها

واژه هنگام انتقال میان این بخش‌ها باید جمله، منبع و Context اصلی خود را حفظ کند.

## فناوری‌های فعلی

این پروژه در حال حاضر از ابزارهای زیر استفاده می‌کند:

- HTML
- CSS
- Vanilla JavaScript
- localStorage
- GitHub Pages

در مرحله‌ی بعد، فایل‌های JSON نیز به پروژه اضافه خواهند شد.

## خارج از محدوده‌ی فعلی

فعلاً این موارد ساخته نمی‌شوند:

- Backend
- دیتابیس واقعی
- حساب کاربری
- Authentication
- هوش مصنوعی
- API دیکشنری خارجی
- React یا Frameworkهای دیگر

این فناوری‌ها ممکن است در نسخه‌های تمرینی بعدی اضافه شوند.

## وضعیت فعلی پروژه

### v0.3.0 — Data-driven Learn ✅

در این نسخه، صفحه‌ی Learn از یک صفحه‌ی ثابت به یک رابط داده‌محور تبدیل شده است.

اطلاعات درس‌ها داخل فایل `data/lessons.json` نگهداری می‌شود و فایل `js/learn.js` مسئول دریافت، بررسی، مرتب‌سازی و نمایش آن‌ها است.

### امکانات این نسخه

- ساخت `data/lessons.json`
- دریافت اطلاعات درس‌ها با `fetch`
- استفاده از `async/await`
- ساخت کارت‌های درس با DOM
- مرتب‌سازی درس‌ها بر اساس `order`
- نمایش عنوان، توضیح، سطح و زمان درس
- نمایش وضعیت Available و Coming soon
- پشتیبانی از Loading State
- پشتیبانی از Empty State
- پشتیبانی از Error State
- پشتیبانی از Success State
- اعتبارسنجی ساختار هر درس
- بررسی یکتابودن `id` درس‌ها
- بررسی یکتابودن `order` درس‌ها
- استفاده از `DocumentFragment` برای ساخت کارت‌ها
- سازگاری کارت‌ها با Classic و Snowy
- آزمایش Navigation با محتوای بلند Learn

### جریان فعلی داده در Learn

`lessons.json → fetch → validation → sorting → DOM rendering → lesson cards`

درس‌ها دیگر به‌صورت تکراری داخل `learn.html` نوشته نمی‌شوند.

فایل `learn.html` فقط ساختار صفحه و محل نمایش درس‌ها را فراهم می‌کند.

### قرارداد فعلی درس

هر درس باید شامل این اطلاعات باشد:

- `id`
- `order`
- `title`
- `description`
- `level`
- `estimated_minutes`
- `status`

مقدار `status` فقط می‌تواند یکی از این دو حالت باشد:

- `available`
- `coming_soon`

شناسه و ترتیب هر درس باید یکتا باشند.

### محدودیت‌های فعلی

نسخه‌ی فعلی هنوز شامل این قابلیت‌ها نیست:

- بازکردن صفحه‌ی کامل هر درس
- تمرین‌های داخل درس
- پیشرفت شخصی کاربر
- درس‌های تکمیل‌شده یا قفل‌شده
- دیکشنری
- ساخت کارت
- Deck
- مرور کارت‌ها
- حساب کاربری
- دیتابیس واقعی
- Backend
- هوش مصنوعی

این قابلیت‌ها در نسخه‌های بعدی و به‌صورت مرحله‌ای تمرین خواهند شد.

## مرحله‌ی بعد

### v0.4.0 — Storage Layer

در نسخه‌ی بعد، یک لایه‌ی مشترک برای ذخیره و بازیابی اطلاعات شخصی کاربر ساخته می‌شود.

فایل پیشنهادی:

`js/storage.js`

این فایل در ابتدا از `localStorage` استفاده خواهد کرد و مسئول عملیات‌هایی مانند موارد زیر خواهد بود:

- ذخیره‌ی کارت
- دریافت کارت‌ها
- حذف کارت
- مدیریت داده‌ی خراب
- نگهداری نسخه‌ی ساختار داده

هدف این است که سایر قسمت‌های پروژه مستقیماً با `localStorage` کار نکنند.

در آینده، پیاده‌سازی پشت این لایه می‌تواند از `localStorage` به Supabase یا یک API واقعی تغییر کند.
